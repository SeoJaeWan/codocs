# 이전 실행기·성능 검사 제거 책임

표준 `pnpm test`는 남은 인접 TypeScript 검사와 Node glob을 그대로 수집한다. UI 실행은 `pnpm test:vscode`의 `test-runner/ui/run.mjs`가 소유하고, 실제 Windows/macOS 수락은 같은 고정 stable·최종 VSIX의 GitHub 실행으로 확인한다.

| 제거한 구현과 검사                                                                                                    | 제거하거나 보존한 계약의 최종 소유자                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| tools/performance의 runner/worker/generator/progress/reporter 및 progress/reporter 검사                               | 벤치마크 자료 생성·시간 통계·진행 보고 자체를 제거했다. 조회·준비·외부 변경의 제품 정확성은 workspace/query, watcher, write 및 MCP/server 인접 검사에 유지한다.                                                                                                                                                                        |
| runtime/performance-contract, performance-report, performance-foundation 및 integration/test-support/performance 전체 | API/UI 지연·워밍업·Loading 시간·저장/전파 표본·메모리·다중 창 성능 측정을 제거했다. 기존 기능 조건의 소유자는 [coverage.md](coverage.md)에 기록한다. 공식 stable 목록의 정확한 버전 선택 assertion은 test-runner/cli.test.mjs로 이동했다.                                                                                              |
| vscode와 language-server의 performance-observation 및 language-server 전용 검사                                       | opt-in JSONL 시각·RSS·계측 비용 기록과 환경 변수를 제거했다. 확장 활성화·서버 시작·연결 실패·복구는 vscode-client/client-manager, language-server/server 인접 검사와 UI 설치 smoke에 유지한다.                                                                                                                                         |
| workspace/query/performance-observation.test.ts                                                                       | 성능 관측 스트림의 이벤트 순서 검사를 제거했다. lazy 초기화·watcher 준비 완료·중단과 오류 복구는 query-initialization, watcher-registration, watcher-recovery 인접 검사가 소유한다. query의 기능적 index-start/index-published callback은 query-reconciliation의 경로별 복구와 write/write.test.ts의 원자적 게시 검사를 위해 유지한다. |
| test-runner의 이전 run/host/CLI mode와 api-progress-reconcile·ui-observer·ui-state 및 전용 검사                       | 성능 mode·시나리오 선택·계측 재조합을 제거했다. 실제 renderer 연결·텍스트 좌표·Hover 앵커·OS modifier 입력은 ui/driver와 ui/driver.test.mjs 및 19개 UI 사례가 소유한다. ui/cli와 인접 검사는 exact 버전·절대 후보/output·CI/OS 제한을 유지한다.                                                                                        |
| runtime/vscode·vscode-paths와 cache-lock 및 인접 검사                                                                 | 자체 실행 경로 탐색·전체 다운로드 트리 지문·공유 다운로드/빌드 잠금·재사용/복구 계약을 제거했다. ui/worker가 공식 downloadAndUnzipVSCode/runVSCodeCommand/runTests helper로 실행별 경로에서 순차 준비하고 설치 버전·Host 버전을 확인한다.                                                                                              |
| lifecycle/lifecycle-host/lifecycle-suite, runtime/lifecycle-evidence 및 인접 검사                                     | 최소 버전·존재하지 않는 suite·timeout/cancel 실패를 만드는 전용 lifecycle 시험을 제거했다. 실제 실패·SIGINT/SIGTERM·실행 시간 제한·스크린샷/로그·자식 정리는 ui/run.mjs가 소유하며 정리 실패는 비정상 결과다.                                                                                                                          |
| run-control, runtime/process/process-worker 및 인접 검사                                                              | 폐기한 실행기의 취소 요청 파일·자체 프로세스 감독/OS 조회 알고리즘과 합성 실패 시험을 제거했다. 실제 UI 실행의 신호와 종료 정리는 ui/run.mjs와 공식 killTree helper가 소유한다. 제품 프로세스 stdout/EOF/재시작의 고유 assertion은 MCP/server/server.test.ts와 language-server/server/server-process.test.ts에 유지한다.               |
| 이전 context/fixtures/workspace-fixture·processes·mcp-client·storage-io-observer 및 인접 검사                         | 소비자가 사라진 API 설치 fixture·서버 PID 선택·MCP 종료 보조 코드를 제거했다. UI fixture 준비/복원은 ui-fixture/ui-context, 실제 제품 IO·EOF·종료·동시 쓰기는 위 인접 책임과 coverage.md의 write-race 소유자에 유지한다.                                                                                                               |

제품의 loader 관측 캐시, catalog cursor 지문, watcher 등록·settle·readiness, 저장 직렬화·재시도·revision 검사는 변경하지 않았다. UI 대기와 실패 정리의 제한 시간은 실행을 끝내기 위한 계약으로 남긴다. 과거 workplan과 실행 결과는 보존한다.
