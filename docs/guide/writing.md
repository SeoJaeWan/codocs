# 작성 원칙과 참조

[전체 순서와 주제](README.md)

## 기본 작성 지침

다음은 제품의 기본 권장 사항이다. 프로젝트의 목적과 독자에 맞게 조정할 수 있으며, 이 지침을 따르지 않았다는 이유로 검증 오류·경고를 만들거나 저장을 차단하지 않는다. `_codocs`·섹션·허용 값·참조 문법 등의 형식 검증은 별개다.

문서 이름이 가리키는 주제와 독자가 해결할 질문을 중심으로 작성한다.
용어의 의미·동작·정책·조건·예외·판단 근거와 책임을 설명한다.
상태 코드만 적지 않고 어떤 조건에서 발생하며 왜 그렇게 판단하는지, 어떤 예외가 있는지 설명한다.
확인되지 않은 이유는 확정 사실로 기록하지 않는다. 미합의 정책을 확정된 동작처럼 쓰거나 기록을 지워 확정된 것으로 만들지 않는다.

새 설명을 추가하기 전에 같은 주제를 다루는 원문을 찾아 먼저 보완한다.
다른 설명은 참조로 연결하고 대상 문서에서 무엇을 확인할 수 있으며 현재 설명에 왜 필요한지 드러낸다.
무엇을 연결하는지 설명하지 않는 “다른 문서를 따른다” 같은 문장만 남기지 않는다.
연결이 있다는 사실만으로 모든 관련 문서를 확인한 것으로 간주하지 않고 판단에 필요한 원문을 추가로 읽는다.

구현 예정·진행·완료 여부, 담당 작업과 PR·이슈 배정 등 개발 진행 상황은 작업 관리 도구에서 관리한다.
개발 진행 상황을 담는 별도 문서도 만들지 않는다. 구현이 계약과 다르면 수정할 작업을 이슈·PR에 기록한다.

### 문서의 목적과 책임

첫 설명에서 무엇을 다루고 독자가 어떤 질문을 해결할 수 있는지 밝힌다.
작업을 설명한다면 무엇을 받아 어떤 판단을 하고 무엇을 반환하거나 변경하는지 적는다.
예를 들어 ‘반품 요청’은 요청의 의미와 정보를, ‘반품 승인’은 요청과 구매 내역을 확인해 승인 여부를 결정하는 과정을 설명할 수 있다.

용어 자체의 의미·구조·성질은 용어를 설명하는 문서에 둔다.
그 용어를 언제 선택하고 어떻게 사용하는지는 해당 작업에서 용어를 참조하며 설명한다.
‘반품 요청’ 문서가 승인과 환불 등 모든 사용처의 처리 규칙까지 담을 필요는 없다.

다른 처리에서 받은 정보를 사용할 때는 어떤 정보를 왜 사용하는지 설명한다.
그 정보의 구조나 계산 방법을 사용처에서 다시 정의하지 않는다.
별도 담당 문서가 없고 현재 주제에 필요한 동작이면 같은 문서에서 설명할 수 있다.
독립적인 질문으로 분리할 때는 기존 설명도 옮기며, 이 구분을 위해 새 문서 타입이나 고정된 절 제목을 만들 필요는 없다.

### 설명의 원본과 연결

정의·규칙·판단 기준은 담당 문서 한 곳에서 관리한다.
다른 문서에서는 그 설명이 필요한 상황과 관계를 적고 참조한다. 표현을 바꾸거나 일부만 요약해도 같은 조건·예외를 다시 규정하면 중복 관리가 된다.

예를 들어 반품 가능 조건을 ‘반품 정책’에서 정했다면 주문 처리 문서에는 그 조건표를 복사하지 않는다.
주문 처리에서 반품 가능 여부를 판단할 때 해당 정책을 확인해야 한다는 맥락과 연결을 남긴다.
현재 상황에 적용하는 예시는 둘 수 있지만 예시의 조건을 새로운 일반 규칙으로 만들지 않는다.

설명을 분리할 때는 기존 위치의 설명을 참조로 대체한다.
중복을 제거한 뒤 독립적으로 답할 질문이 남지 않는 문서는 합치고 참조를 갱신한다.
규칙 하나를 바꾸기 위해 여러 문서의 같은 설명을 고쳐야 한다면 중복 관리 여부를 확인한다.

### 문단과 간격

같은 설명에 속하는 문장은 줄바꿈으로 이어서 작성한다.
설명의 관점·조건·단계가 바뀔 때 빈 줄로 문단을 나눈다.
제목·목록·표는 주변 문단과 구분하며 YAML 들여쓰기를 유지한다.
문장마다 빈 줄을 넣거나 모든 빈 줄을 일괄 제거하지 않는다.

## 설명 범위와 분리 권장

설명 분리는 한 문서의 일부를 독립적으로 찾고 유지할 문서로 나눌지 판단하는 작업이다.
한 주제를 설명하는 데 여러 개념이 필요하다는 이유만으로 문서를 나누지 않는다.
다른 설명이 필요하면 참조를 연결하고 현재 주제에서 필요한 이유·순서를 적는다. 대상 문서의 규칙 전체를 복제하지 않는다.

다음은 프로젝트의 독자와 유지 방식에 맞게 조정할 수 있는 권장 기준이다.

| 판단 기준                                | 권장 처리                                                |
| ---------------------------------------- | -------------------------------------------------------- |
| 다른 곳에서도 같은 설명이 필요하다       | 기존 문서를 먼저 확인하고 필요하면 별도 문서로 분리한다. |
| 이름을 붙여 따로 찾아볼 만한 주제다      | 별도 문서로 분리한다.                                    |
| 다른 내용과 독립적으로 변경되는 규칙이다 | 별도 문서로 분리한다.                                    |
| 현재 주제 안에서만 의미 있는 조건·예외다 | 현재 문서에 유지한다.                                    |
| 길지만 계속 같은 질문에 답하고 있다      | 우선 제목·문단으로 정리한다.                             |

분리한 문서는 다른 곳에서 찾아 읽어도 주제와 적용 조건을 이해할 수 있게 작성한다.
원래 문서에는 연결과 함께 설명이 필요한 시점·이유를 남긴다. 단순 참조 목록만 남겨 원래 질문에 대한 답을 잃지 않는다.
참조 횟수나 문장 길이만으로 자동 분리하지 않는다.

형식·ID 및 이름 충돌·`parent`·참조 오류를 검증하며 문서의 서술 방식이나 자연어 규칙의 타당성을 자동 판정하지 않는다.

## 이름과 폴더 구성

`_codocs.id`는 프로젝트 내 유일한 영어 식별자이며 ID 기반 조회·수정의 기준이다. `_codocs.name`은 원하는 언어의 문서 이름이며 참조와 표시의 기준이다.
ID만 변경하고 문서용 이름을 유지하면 참조는 유지된다. ID를 바꿔도 과거 ID는 남기지 않는다.

문서의 소속은 `_codocs.parent`에 상위 문서의 이름으로 명시한다. 목차 문서가 세부 문서를 참조하면 세부 문서의 `parent`에 그 목차 문서를 쓰는 식이다.
`parent`는 참조가 아니므로 역참조를 만들지 않는다. 다른 영역의 문서를 참조한다는 이유만으로 그 영역의 문서를 `parent`로 쓰지 않는다.
폴더는 주제별로 묶을 수 있으며 제품이 고정 계층을 요구하지 않는다. 소속을 파일 경로에서 추론하지 않는다.

목차 문서는 그 영역의 책임과 세부 문서가 답하는 질문을 안내한다.
목차 문서와 개별 문서는 같은 형식이며 종류별 폴더로 구분할 필요가 없다.

## 이름 참조

참조는 ID가 아닌 문서의 `name`을 사용한다. `[[이름]]`은 문서를, `[[이름:섹션]]`은 그 문서의 섹션을 가리킨다. 다음은 ‘문서’와 ‘설명 분리’라는 문서를 작성한 프로젝트의 예시다.

```yaml
개요: |
  [[문서]]에서 필수 속성을 확인하고 작성할 내용을 정한다.
  독립적으로 관리할 설명인지는 [[설명 분리]]의 기준으로 판단한다.
```

- 이름을 쓰면 프로젝트의 모든 문서에서 정확히 찾는다.
- trim이나 대소문자 보정을 하지 않으므로 앞뒤 공백과 대소문자를 작성한 그대로 비교한다.
- 이름은 프로젝트 전체에서 유일해야 하므로 같은 이름의 문서가 둘 이상이면 `duplicate_name` 오류이고 그 이름의 참조는 모호하다.
- `[[이름]]`으로 자기 문서를 가리키는 참조는 연결하지 않는다.

## 섹션 참조

`[[이름:섹션]]`은 첫 번째 escape되지 않은 콜론 앞을 문서 이름, 뒤를 섹션 이름으로 읽는다. 섹션 이름은 그 문서에서 `_codocs`를 뺀 최상위 키와 공백·대소문자까지 정확히 같아야 한다.

```yaml
개요: |
  환불 기준은 [[환불:환불정책]]에서 확인한다.
  예외는 같은 문서의 [[환불:예외]]를 본다.
```

- 문서와 섹션이 모두 있으면 링크가 되고, 편집기에서 누르면 그 섹션 키로 이동한다.
- 문서는 있지만 섹션이 없으면 `section_reference_not_found` 오류이며 링크는 만들지 않는다. 문서가 없으면 `reference_not_found`다.
- 같은 문서의 섹션을 가리키는 `[[환불:예외]]`는 같은 파일의 그 섹션으로 이동하는 링크이며 진단하지 않는다. 문서 사이의 참조가 아니므로 `references`·`referencedBy`에는 들어가지 않는다.
- 이름과 섹션 이름에 콜론이 들어가면 각각 `\:`로 쓴다.

참조는 모든 섹션의 문자열에서 찾는다. `_codocs`의 이름·ID·`parent`에서 참조처럼 보이는 문자열은 해석하지 않는다.

## 참조 안의 특수 문자

참조를 여는 두 대괄호 바로 앞에 연속된 백슬래시가 홀수 개이면 리터럴이다. 이름에 들어가는 콜론은 `\:`로 작성한다.
예를 들어 이름 `주문:확인`은 `주문\:확인`으로, 그 문서의 섹션 `취소:환불`은 `주문\:확인:취소\:환불`로 적는다.

```yaml
개요: |
  \[[문서]]는 연결하지 않는 글자다.
```

작은따옴표와 블록 문자열은 백슬래시를 그대로 보존한다. 큰따옴표 YAML 안에서는 백슬래시 자체를 한 번 더 escape한다.

```yaml
개요: "\\[[문서]]"
```

빈 이름, 이름 안에 남은 대괄호, escape되지 않은 콜론이 둘 이상이거나 콜론 앞·뒤가 빈 표기(`[[:가]]`, `[[가:]]`), 닫히지 않은 참조는 `invalid_reference` 오류다.
`[[가:나]]`는 이름이 `가:나`인 문서가 아니라 문서 `가`의 섹션 `나`를 가리킨다. 콜론이 들어간 이름은 `\:`로 쓴다.

## 코드와 특정 행 연결

코드·테스트·일반 텍스트에서 문서 전체를 `@codocs [[문서 이름]]`, 특정 행을 `@codocs [[문서 이름]]#L11`, 행 범위를 `@codocs [[문서 이름]]#L11-L12`로 참조한다. 행은 1부터 시작하고 범위 끝을 포함한다.

문서의 연결 행에서 참조한 코드 위치로 돌아갈 수 있다. 여러 코드 출현은 호버에서 각각 선택하고, 문서 전체 참조는 첫 행 앞의 Inlay Hint로 표시한다. 단일 출현은 IDE 이동 제스처로 연다. 행 번호는 문서의 실제 행을 가리킨다.
