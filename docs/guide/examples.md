# 네 문서 연결 예시

[전체 순서와 주제](README.md)

[가상 프로젝트 YAML](../../examples/.codocs)은 모두 교육용이다. 실제 업무 정책이나 권장 배송 조건이 아니다.
네 파일을 프로젝트의 `.codocs`에 함께 복사하면 이름 참조를 확인할 수 있다. 네 문서는 모두 `parent`가 없는 최상위 문서다.

| 파일                                                                | 책임                                      | 연결                              |
| ------------------------------------------------------------------- | ----------------------------------------- | --------------------------------- |
| [order.yaml](../../examples/.codocs/order.yaml)                     | 가상 주문의 의미                          | 처리 절차와 다른 이름의 사용 맥락 |
| [fulfillment.yaml](../../examples/.codocs/fulfillment.yaml)         | 요청을 받아 판단하고 상태를 기록하는 절차 | 용어와 단일 정책 원문             |
| [shipping-policy.yaml](../../examples/.codocs/shipping-policy.yaml) | 접수 기준의 유일한 소유자                 | 판단 대상인 용어                  |
| [receipt.yaml](../../examples/.codocs/receipt.yaml)                 | 가상 접수건이라는 다른 이름의 사용 맥락   | 원래 용어                         |

한 문서에 다른 이름을 따로 적어 두어도 이름 참조가 연결되지 않는다. 별도 이름 문서는 독립적인 사용 맥락을 설명하고 원뜻을 참조한다.

정책 조건은 shipping-policy 한 곳에 있다. 처리 절차는 정책을 참조하고 판단 뒤 행동을 설명한다.
이름·경로를 바꾸거나 설명을 분리했다는 이유만으로 기존 ID를 바꾸지 않는다. 예시에서는 `sample-receipt`를 유지한다.

절차의 `[[가상 배송\:정책]]`은 이름 안의 콜론을 `\:`로 적은 참조다. escape하지 않은 콜론은 문서 이름과 섹션 이름을 나누는 표기이므로 `[[가상 배송:정책]]`은 문서 `가상 배송`의 섹션 `정책`을 가리킨다.
정책의 두 예문은 YAML 작은따옴표·큰따옴표가 해석된 뒤 모두 백슬래시 하나를 가진 리터럴 참조가 된다. 두 문자열은 연결을 추가하지 않는다.
자세한 표기는 [참조 이스케이프](writing.md#참조-안의-특수-문자)를 따른다.

처음부터 상호 참조 두 파일을 MCP로 만들려면 [A → B → A 순서](updating.md#상호-참조를-처음-만드는-순서)를 사용한다.
