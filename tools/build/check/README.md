# 검사 책임 대응표

`pnpm test`는 제품 인접 테스트, 자체 lint 규칙, 빌드 설정·원본 예제, CI·릴리스 판단을 표준 Vitest/Node glob으로 실행한다. `pnpm check`는 정적 검사·빌드·인접 테스트 뒤 이미 빌드한 결과의 최종 패키지를 검사한다. `build-checks.test.ts`는 별도 `vitest.checks.config.mjs`에서 실행하며 내부 패키지를 pack/install하지 않는다.

| 제거하거나 축소한 검사                                         | 보호 조건과 최종 소유자                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `change-plan-contract` 외부 JS 소비자                          | 바이트 revision·원문/입력 불변·ID 변경·충돌·미저장: `packages/core/src/change-plan/change-plan.test.ts`, `packages/workspace/src/change-plan/change-plan.test.ts`                                                                                                                              |
| `matcher-contract` 외부 JS 소비자                              | 현재/이전 ID·pluralize·UTF-16 범위·부분 결과: `packages/core/src/matcher/matcher.test.ts`                                                                                                                                                                                                      |
| `name-references` 외부 JS 소비자                               | 이름 추출·중복/모호성·색인/역참조·변경 후보: `packages/core/src/references/references.test.ts`, `packages/core/src/catalog/catalog.test.ts`, 위 change-plan 테스트                                                                                                                             |
| `query-contract` 외부 JS 소비자                                | 목록·상세·입력 오류·없음/충돌·부분 결과: `packages/mcp/src/query/query.test.ts`, `packages/workspace/src/query/query.test.ts`, `candidate.test.ts`                                                                                                                                             |
| 내부 tarball의 workspace 로딩·링크 syscall 기능                | 원문/확장 필드·파싱/스키마 진단·실제 경로·외부/깨진 링크 거부: `packages/workspace/src/loader/loader.test.ts`, `packages/workspace/src/paths/paths.test.ts`                                                                                                                                    |
| 외부 파서·검증기 소비자                                        | 단일 YAML 매핑·UTF-16 위치·오류 코드/심각도·입력 불변: `packages/core/src/parser/parser.test.ts`, `packages/core/src/validator/validator.test.ts`                                                                                                                                              |
| 내부 JS/d.ts 소비자와 subpath 거부                             | 비공개 패키지의 독립 배포 보장은 제거한다. 소스 타입은 `pnpm typecheck`, 패키지 진입점/의존 방향은 자체 `eslint-rules.test.ts`와 `pnpm lint`가 소유한다. 공개 제품 manifest·진입점은 최종 패키지 검사에 남는다.                                                                                |
| 외부 소비자의 실제 예제 관계                                   | 네 원본 예제의 유효성·참조/역참조·deprecated 경고는 `tools/build/release-assets.test.ts`에서 소스 API로 유지한다. 배포 파일 목록·바이트·상대 링크는 `release-assets.mjs`가 두 최종 제품에서 대조한다.                                                                                          |
| 내부 패키지별 가이드 pack/install 소비                         | 전체 가이드/예제 자산은 최종 MCP tarball·VSIX에서만 확인한다. 가이드 생략·여섯 주제·잘못된 입력·파일 접근 실패는 `packages/mcp/src/guide/guide.test.ts`에 유지한다.                                                                                                                            |
| 최종 MCP의 모든 상세 도구 호출·stdout/EOF                      | `verifyMcp`는 외부 설치·시작·SDK connect·서버 버전·`listTools`만 실행한다. 도구 기능은 위 query/guide와 `tool-input`; 저장/복구는 `authoring.test.ts`, `state.test.ts`; stdout·큰 요청·프로젝트 선택·EOF/정리는 `server.test.ts`; 동시 revision/ID 충돌은 `write-race.test.ts`에 유지한다.     |
| 별도 tsc 오류 fixture·전체 제품 기능 번들                      | 타입 검사는 `pnpm typecheck`, CJS/로컬 ESM 포함·vscode external·source map 설정은 `tools/build/build.test.ts`. 최종 검사에서 실행/선언 파일·테스트 제외·서버 번들 동일성·notice를 확인한다.                                                                                                    |
| 별도 동적 버전 설치 반복                                       | `release-contract.test.mjs`가 서로 다른 제품 버전 읽기와 manifest identity 거부를 확인한다. 실제 최종 tarball/VSIX manifest와 MCP initialize 버전은 `verify-release.mjs`에서 현재 제품 manifest와 대조한다.                                                                                    |
| broad `development-checks.test.ts`                             | 자체 패키지 경계·해석 별칭·한국어 JSDoc은 `eslint-rules.test.ts`; 도메인 문맥/별칭/자동 수정/type-only는 기존 `domain-value-rule.test.ts`. Promise·외부 naming/JSDoc plugin·ESLint CLI·frozen 불일치 자체 동작 fixture는 제거하고 실제 `pnpm lint`·`pnpm typecheck`·frozen install을 사용한다. |
| 외부 Changesets 버전/재계산·shallow 복구 suite                 | 외부 CLI 알고리즘을 재검사하지 않는다. 자체 제품 version/name/filename 검증은 `release-contract.test.mjs`; 증가 제품 선택/감소 거부는 `release-publish.test.mjs`; 최신 develop·main 동기화·빈 status·직접 parent 거부는 `release-flow.test.mjs`.                                               |
| clone한 Changesets Action과 API mock 서버                      | Action 내부 Draft 생성/갱신·changelog 구현은 제거한다. 선택한 고정 revision·create Draft 입력·권한·캐시·Node·게시 재빌드 금지 연결은 `release-flow.test.mjs`의 실제 workflow 읽기로 유지한다. 외부 manifest 다운로드/해시/입력 스키마 재검사는 하지 않는다.                                    |
| `ci-release.integration`의 후보/게시 재시도·변조 흐름          | source/tree/blob/제품 SHA/run/attempt/artifact 연결은 `release-contract.test.mjs`, `release-source.test.mjs`; PR 실행 취소·집계·댓글은 GitHub Actions `CI` workflow가 소유한다. 만료/변조/다른 base/부분 재시도/역순 기록/공개 바이트 충돌은 `release-publish.test.mjs`.                       |
| `ci-release.integration`의 보호 gate·sync 흐름                 | 실제 보호 gate 성공/strict 누락과 보호 조건은 `release-flow.test.mjs`. merge/squash/rebase·소비 기록/동시 새 입력·경합/stale 차단·호출자 identity 없는 실제 subprocess는 `release-sync.test.mjs`. fixture는 명시한 버전 결과를 쓰고 외부 version CLI를 반복하지 않는다.                        |
| `release-native.integration`과 후보 fixture의 전체 제품 재실행 | 최종 MCP/VSIX 구성은 위 최종 패키지 검사. 설치된 확장 활성화/서버 연결·실제 UI 기능은 GitHub Actions의 `pnpm test:vscode`가 소유한다. 이 로컬 검사에서 VS Code 또는 lifecycle 전용 suite를 실행하지 않는다.                                                                                    |

대응표는 소유 경계를 설명한다. 현재 후보의 통과 여부와 Windows/macOS UI 결과는 실제 실행 증거로 별도 기록한다. 외부 소비자 검사의 제거를 비공개 패키지의 배포 호환성 보장으로 표현하지 않는다.
