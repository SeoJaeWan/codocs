Documents can now live in `.codocs` folders inside subfolders of the project, such as `packages/core/.codocs/a.yaml`, in addition to the root `.codocs`. A subfolder `.codocs` is recognized only where code reference collection would read files (Git tracks it or `.gitignore` does not exclude it, and the root `.codocsignore` does not exclude it); documents in other locations are not indexed. A document belongs to the outermost `.codocs` in its path. Scanning, watching, `codocs_get`, `codocs_list`, `codocs_validate` (including `path`) and rename now cover every recognized `.codocs`, and a subfolder `.codocs` created or deleted while the server runs is picked up without a restart; editing `.codocsignore` recalculates which locations are recognized. IDs and names must be unique across all `.codocs`. `codocs_write` create and move create the missing `.codocs` and outer folders in both single and `changes` requests, a failed `changes` request removes every folder it created, and emptied folders are removed only up to the owning `.codocs`. Creating or moving into an excluded location is rejected with `invalid_workspace_path` and a message that names the location. The tool descriptions now include a subfolder example (`packages/core/.codocs/a.yaml`).

프로젝트 루트의 `.codocs`뿐 아니라 `packages/core/.codocs/a.yaml`처럼 하위 폴더의 `.codocs`에도 문서를 둘 수 있다. 하위 폴더의 `.codocs`는 코드 참조 수집이 파일을 읽는 위치(Git이 추적하거나 `.gitignore`가 제외하지 않았고 루트 `.codocsignore`도 제외하지 않은 위치)에서만 인정하며 다른 위치의 문서는 색인하지 않는다. 문서는 경로에서 가장 바깥 `.codocs`에 속한다. 탐색·감시·`codocs_get`·`codocs_list`·`codocs_validate`(`path` 포함)·이름 변경이 인정된 모든 `.codocs`를 대상으로 하고, 서버 실행 중 하위 `.codocs`를 만들거나 지우면 재시작 없이 반영하며 `.codocsignore`를 고치면 인정 범위를 다시 계산한다. ID와 이름은 모든 `.codocs`에서 유일해야 한다. `codocs_write`의 create·move는 단일 요청과 `changes` 모두 없는 `.codocs`와 바깥 폴더를 만들고, `changes`가 실패하면 이번 요청이 만든 폴더를 모두 지우며, 비게 된 폴더는 소유 `.codocs` 바로 아래까지만 지운다. 제외된 위치로의 create·move는 그 위치를 알리는 메시지와 함께 `invalid_workspace_path`로 거부한다. 도구 설명에 하위 폴더 예시(`packages/core/.codocs/a.yaml`)를 더했다.
