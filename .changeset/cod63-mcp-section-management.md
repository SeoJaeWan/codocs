Add whole-document replacement and reference protection to MCP, report code-file reference diagnostics in `codocs_validate` and `codocs_refresh`, and remove `codocs_duplicates`. `codocs_write` accepts `{"mode":"replace","id","revision","document"}`, where `document` is the whole document including `_codocs`; top-level sections that are left out are deleted, top-level comments and the original text of unchanged keys are preserved, and an identical document is a no-op (`saved: false`, `changed: false`). `replace` cannot be combined with `set` or `unset`, unknown properties are `invalid_input`, and changing `_codocs.name` is still `name_change_not_allowed`. `update` and `replace` now reject a change that newly breaks a confirmed reference from another document or from an `@codocs` marker in a code file with `reference_broken` (the diagnostic carries the referring file and range), and reject with `code_evidence_incomplete` when the code files that must be checked could not be read; references that were already broken and unrelated errors do not block the write, and a rejected request leaves the file bytes unchanged. `codocs_validate` now also returns code-file diagnostics (`path` is the code file, `range` is the marker) together with `codeScanStatus` (`collecting`, `complete` or `incomplete`), `diagnosticsComplete` and `codeFailures`; `scanStatus` still describes the document scan only. With `path`, it must be a `.codocs` YAML file (otherwise `invalid_path`) and only code diagnostics whose candidates include that file are added. `codocs_refresh` builds the code reference index on its first call and returns `errorCount`, `warningCount` and `countsComplete` computed over the returned `diagnostics`, plus `codeScanStatus` and `codeFailures`. Code references that cannot be resolved (`invalid`, `missing`, `missing_section`, `ambiguous`) are errors in MCP and in VS Code, and `unconfirmed` stays a separate warning. `codocs_duplicates` and its internal duplicate-detection, cursor and release inventory are removed, so calling it is an unknown-tool error; `duplicate_id`, `duplicate_name` and duplicate YAML key validation are unchanged.

MCP에 문서 전체 교체와 참조 보호를 추가하고, `codocs_validate`와 `codocs_refresh`가 코드 파일의 참조 진단을 알리게 하며, `codocs_duplicates`를 제거합니다. `codocs_write`는 `{"mode":"replace","id","revision","document"}`를 받으며 `document`는 `_codocs`를 포함한 문서 전체입니다. 생략한 최상위 섹션은 삭제되고, 문서 최상위 주석과 바뀌지 않은 키의 원문은 보존되며, 같은 문서는 변경 없음(`saved: false`, `changed: false`)입니다. `replace`는 `set`·`unset`과 함께 쓸 수 없고 알 수 없는 속성은 `invalid_input`이며, `_codocs.name` 변경은 여전히 `name_change_not_allowed`입니다. `update`와 `replace`는 다른 문서나 코드 파일의 `@codocs` 표기에서 확정되어 있던 참조를 새로 끊는 변경을 `reference_broken`으로 거절하고(진단에 참조를 쓴 파일과 위치가 담김), 확인해야 하는 코드 파일을 읽지 못했으면 `code_evidence_incomplete`로 거절합니다. 이전부터 깨져 있던 참조와 무관한 오류는 저장을 막지 않으며 거절한 요청은 파일 바이트를 바꾸지 않습니다. `codocs_validate`는 이제 코드 파일 진단(`path`는 코드 파일, `range`는 표기 위치)과 `codeScanStatus`(`collecting`·`complete`·`incomplete`), `diagnosticsComplete`, `codeFailures`를 함께 돌려주며 `scanStatus`는 문서 탐색만 나타냅니다. `path`는 `.codocs` YAML 파일이어야 하고(아니면 `invalid_path`) 그 파일을 후보로 하는 코드 진단만 더합니다. `codocs_refresh`는 첫 호출에서 코드 참조 색인을 만들고, 반환한 `diagnostics`로 계산한 `errorCount`·`warningCount`·`countsComplete`와 `codeScanStatus`·`codeFailures`를 돌려줍니다. 해석하지 못한 코드 참조(`invalid`·`missing`·`missing_section`·`ambiguous`)는 MCP와 VS Code에서 오류이고 `unconfirmed`는 따로 경고로 남습니다. `codocs_duplicates`와 그 내부 중복 검사·커서·배포 검사 목록을 제거하므로 호출하면 알 수 없는 도구 오류입니다. `duplicate_id`·`duplicate_name`과 YAML 중복 키 검증은 그대로입니다.
